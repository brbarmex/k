Início / Fail path / C09

C09 — Queda de uma AZ na Azure

Fail path
Status na fonte: ✅ Atualizado (modelo v1)

1. Visão geral do cenário

Uma AZ da Azure cai (por exemplo, Z3). Z1 e Z2 seguem como maioria dos learners (2 de 3), então o gate segue satisfeito. Nada muda para o cliente. Quando Z3 volta, faz catch-up pelo log antes de contar de novo para o gate: só conta depois de responder ao AppendEntries no termo atual, com termo, índice e identidade. Se duas AZs da Azure caem, é como a Azure inalcançável: com DEGRADED_POLICY=accept entra o modo degradado com lease (C12); com reject a escrita responde 503 PENDING e o RPO continua 0.

3. Legenda e etapas

  1. A AZ 3 da Azure cai; Z3 fica fora.
  2. A líder replica N para os votantes AWS e para Z1, Z2 e Z3 (sem resposta de Z3).
  3. 2 de 3 votantes AWS e 2 de 3 learners (Z1 e Z2) confirmam o fsync; o gate libera.
  4. Z3 volta e recebe as entradas que faltam pelo próprio Raft (MsgApp), enquanto o log do Raft da líder ainda retém o que Z3 precisa. Se a compactação já passou do índice de Z3, Z3 volta por reconstrução em tabela sombra (C33).

1Duas AZs da Azure caem Falhas e tratativas

Contexto
Com só um learner de pé, não há maioria Azure e o gate para. Para a AWS é igual à Azure inteira inalcançável, e o comportamento passa a depender da política: com accept abre janela de RPO > 0, com reject as escritas param.
O que a fonte define
Modo degradado com lease se accept (C12, C32) ou 503 PENDING se reject; ressincronização depois (C13).
Sugestão de encaminhamento (inferência, não decidida)
Incluir no teste de caos a queda de duas AZs Azure em sequência (não simultânea), conferindo que t_c é o instante em que se perdeu a maioria e não a primeira queda. Medir o tempo até o RESTORE quando as AZs voltam.

2Z3 volta com disco novo Falhas e tratativas

Contexto
Se o learner volta sem o disco, não tem log nem histórico confiável. Se voltasse com a mesma identidade, poderia contar para o gate uma durabilidade que não tem mais.
O que a fonte define
Identidade nova como learner e reconstrução (C21, ADR-034).
Sugestão de encaminhamento (inferência, não decidida)
Testar a volta de learner com disco zerado e conferir que ele só conta no gate depois de responder ao AppendEntries no termo atual com a identidade nova. Medir o tempo de reconstrução, porque durante ele o gate depende dos dois learners restantes e mais uma falha leva à degradação.
